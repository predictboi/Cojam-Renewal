# Cojam platform: decisions so far

Founder decisions for the operating platform (recorded 2026-11-26). The development plan from the document session is the scope; this file holds what was decided in chat.

| Topic | Decision |
| --- | --- |
| Scope | Only what the development plan contains. Ignore the concept previews on the landing |
| Where it lives | This repository, a new folder. Served on `app.cojam.app` |
| Play surface | Installed PWA only, mobile first. In an ordinary browser tab (desktop or mobile) the platform shows a PWA install prompt and the existing swap; no play there |
| Swap site | `cojam.app` stays as it is |
| Login | Privy, email login only (one time code to the email address). No social providers, no external wallet connect (changed from social login on 2026-11-26) |
| Settlement | On chain contracts on Kaia |
| Gas | Cojam pays for staking, predicting and point to token conversion. Withdrawal (moving assets to another wallet) is paid by the user |
| Market operations | Admin automation: AI drafts and posts markets and sets the answers |
| Languages | English source, Korean and Japanese, each reviewed for native voice |
| Legal | Deferred by the founder |
| Process | Screen spec and development plan drafted by Opus agents, reviewed by Fable; design by Fable in the landing's colours; match needed UI components |
| Sponsored gas with Privy | Verify first whether Privy embedded wallets can sign Kaia fee delegated transactions. If not, users sign a message and a Cojam relayer sends the transaction (contracts designed for that). Same experience either way |
| Deposits | Existing holders send new CT from their own wallet (Kaia Wallet and others) to their Privy wallet address; the PWA needs a deposit screen |
| Answer setting | Fully automatic by AI, no human approval step. Markets are point markets, so the risk is small; a wrong answer is checked afterwards and compensated |
| Points | On chain and non transferable: no transfer, no approve, no transferFrom between holders. Balances change only through the platform contracts (earning, predicting, payouts, point to token conversion) |
| Prediction transactions | One transaction per swipe, sent in the background. The next card shows at once without waiting for confirmation (optimistic). Failed sends retry quietly and surface only if they keep failing |
| Play key | Adopted: the Privy wallet authorises a local play key once; swipes are signed locally by that key, which can only predict |
| Review defaults | Every proposed default in `REVIEW.md` section B is accepted: 09:00 KST day and Monday week boundary, hit points about 6 hours after the answer, wrong answers compensated and never clawed back, the anti abuse package, qualified players and a 10,000 CT weekly pool cap, staking rules and reserved interest, KRW shown in Korean only, no notifications at launch |
| Owner key | The existing master wallet `0xd9dA67b7dcf94C2837d55614A430EA4Ff477eCAb` owns both platform contracts |
| Schedule | Ignore the plan's dates: build as fast as possible with the founder in the loop |
| Deploy | Render; DNS on Cloudflare |
| Still open | Reward funding amounts at launch (conversions, airdrops, staking interest); external audit before mainnet |
| Email allow list | Email only login stays. Sign up is limited to an allow list of major mail providers (for example gmail.com, naver.com, kakao.com, daum.net, hanmail.net, icloud.com, outlook.com, hotmail.com, yahoo.co.jp; editable in the admin); other domains see a clear message. Addresses are normalised before the check (lower case, Gmail dots and plus tags removed, plus tags removed elsewhere) and one normalised address is one player. Enforced by the server before a wallet is registered as a player, whatever Privy itself allows |
| Abuse blocking | Launch with email login and the allow list; no phone verification for now. A recurring job (hourly, and at every sign up) checks new and existing accounts for abuse patterns: many sign ups from one network or device, sign up bursts, look alike addresses, identical answer sequences and timing, accounts that only convert. Accounts above the threshold are blocked automatically (frozen on chain: no predicting, no conversion, no airdrop, no sponsored gas); borderline ones go to a review list in the admin. The admin shows every blocked account with the reason and can unblock it; both blocking and unblocking are done with the operator key (no master wallet signature). Points already earned are not debited |
| Prediction card | Every prediction carries an image and the card is image led, in a deck with depth (cards behind the front one, offset and softened). Card motion quality is a priority: drag follows the finger, throw on release, spring advance. The terminal view shows a thumbnail. Question images are generated by an image AI for each question when it is drafted (no real people, team logos or trademarks in the prompt), stored by us, with a category illustration as the fallback when generation fails or is rejected |
| Language behaviour | The app opens in English by default for everyone. Korean and Japanese are chosen by the user from the language control and remembered. No automatic switch by device language |
| Question content languages | When the AI drafts a question it writes the title, the two choices and the answer rule natively in English, Korean and Japanese (written for each language, not translated word for word) and the server stores all three; the app shows the one for the chosen language. The contract hash covers all three texts |
| Design bar | The PWA must read as a high grade production app: an independent review, then a polish pass on the findings, before build |
| Undo | After a swipe the next card shows at once. For 3 seconds the player can press Undo: the previous card comes back to the front and is picked again. Without Undo the transaction is sent after 3 seconds. Undo acts on the most recent pick only |
| Ranking ties | Confirmed: no split prizes; with the same points, whoever reached the total first ranks higher, and the ranking screen says so |
| Answer colours | The two answers of a prediction have their own colours everywhere (button, drag stamp, pick line): left (no, down, under) coral, right (yes, up, over) sky blue, equal in visual weight, ink text on both. Lime is not used for an answer, so neither answer looks recommended (changed from coral and lime on 2026-11-27) |
| Visual direction | The brand's character sits on the prediction deck, the blue grid header and the display numerals. Every other surface is quiet and flat: sections and hairline dividers instead of stacked bordered cards, heavy ink border and offset shadow only on the main action and the prediction card, a three step radius scale (buttons are not full pills), no lime pill on the current tab, numbers placed directly on the surface |
| Wallet address | On the wallet and profile the address is shown short (`0x7A3f…1C7e`) as a small chip with a copy icon next to the balance; a tap copies the full address. The full address and QR are on the deposit screen only |
| Friend invites | Added to scope. A player has an invite code and link. The inviter earns a bonus of 10% of every point the invited friend earns (completion and hit rewards), paid on chain at the same moment, on top of the friend's points (nothing is taken from the friend). One level only. The link is fixed once at sign up and cannot be changed; no self invites. The rate is an admin parameter (0 to 20%, default 10%). Invite bonus points can be converted to CT but do not count toward the weekly ranking. A frozen friend pays no bonus. Bursts of sign ups under one inviter go to the abuse checks |
| Welcome bonus | An invited friend gets +100P once, when they complete their first full day of 5 (not at sign up). Admin parameter |
| Invite code and PWA | A link opened in the browser cannot reach the installed app (separate storage on iOS), so the Gate shows and copies the invite code and the first run screen has an optional code field. Sharing the invite link is the one sharing feature in the product |
| Support contact | `help@cojam.app` (shown on the account on hold screen and wherever the app offers help) |
| Blocked accounts and gas | No exception: a blocked (frozen) account gets no sponsored gas at all. It can still claim staking interest and withdraw principal after the lock, paying its own KAIA |
| Next work | Admin design and the missing PWA states in parallel with contract development; the Privy spike starts when the founder provides the Privy App ID |
| Privy | App ID `cmwxqqrt0017p0gl5hi2gewh7` (public, used by the PWA). The App Secret is never written in chat or in the repository: it goes only into the Render environment variable `PRIVY_APP_SECRET` of the platform API service when that service exists |
| Staking interest funding | The founder funds 500,000 CT of staking interest at launch (2026-11-26). Proposed launch cap on total principal (`maxTotalPrincipal`): 1,850,000 CT, the amount whose interest is covered even if every position took the highest rate (365 days, 27%: 500,000 / 0.27 = 1,851,851 CT). Sent only after the staking contract is deployed on mainnet, to that contract address |
| Staking cap per user | One address may hold at most 1,000,000 CT of open principal in total across its positions (founder, 2026-11-26). Enforced by the staking contract, owner adjustable; the launch cap on total principal stays 1,850,000 CT |
| On hold: staking and invites | An account on hold cannot open new stakes and cannot invite (code and link hidden). While the inviter is on hold, no invite bonus is paid for points their friends earn in that time (not paid later either); bonus already received is kept |
| On hold: ranking | An account on hold is left out of the prize ranks: the players below move up one place. It still sees its own points, marked "No prize" |
| Invite code entry | At first run, or once within 24 hours of sign up from Profile (covers a first run that happened offline). After that the link is fixed for good |
| Question timing | Every question of a day stays open for the whole day: all five close together at the end of the day (09:00 KST next day) and the outcome must become known only after that close. No intraday closes, so anyone arriving at any hour can finish all 5. The AI drafter rejects a question whose outcome is known before the day ends |
| Admin destructive button | The admin (only) has a fourth button look for destructive confirmations (block account, void a question, cancel): red, used only inside the confirmation step. The PWA keeps three looks |
| Compensation points | Points paid as compensation for a corrected answer count in the weekly ranking of the week the question belonged to if that week's airdrop has not been sent yet, otherwise in the current week |
| Welcome bonus with a late code | A friend who adds the invite code from Profile within 24 hours gets the same +100P welcome bonus (once, after the first full day) as one who entered it at first run |
